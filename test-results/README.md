## About Agentic Testing (Proof of Concept)

These test results are generated by **AI agents** (Claude Code sub-agents) that autonomously navigate the application using Playwright browser automation. Each agent assumes a persona with a specific role and tests issues assigned to that persona by reading acceptance criteria, interacting with the UI, inspecting API responses, and taking screenshots.

**This is a proof of concept.** Results should be interpreted with care:
- **False positives possible** — agents may report FAIL when the feature works (wrong page, misinterpreted UI)
- **False negatives possible** — agents may report PASS when a bug exists (missed edge cases)
- **CANNOT_TEST is common** — agents sometimes fail to reach the right page or interact correctly
- **Post-test human review is essential** — several findings were reclassified after manual investigation in previous runs

## Critical Findings

### 1. CRITICAL: Municipality Employee PII Publicly Exposed (#394)
**Agent:** Security Officer | **Impact:** GDPR violation, privacy breach

The public API (`/api/publications?_schema=organisatie&type=Gemeente&_extend[]=contactpersonen`) returns full contact details (names, email addresses, phone numbers, roles) of municipality employees without authentication. The frontend detail pages also display this data. The RBAC model in `softwarecatalogus_register.json` specifies contactpersoon as NOT public read — this is not enforced.

**Evidence:** 6 municipality contacts with PII exposed in a sample of 5 organisations (Aa en Hunze, Aalsmeer, Aalten).

### 2. CRITICAL: Samenwerking Functionality Broken (#57)
**Agent:** Samenwerking | **Impact:** Entire samenwerking workflow non-functional

Switching to "Test Samenwerking" causes `TypeError: Cannot read properties of undefined (reading 'includes')` in `ac-dashboard.js:200`. Dashboard shows "Geen wizards beschikbaar" with 404 errors. No samenwerking-specific features exist.

### 3. HIGH: Export Endpoint Broken (#15, #355)
**Agent:** Gemeente | **Impact:** Data export completely non-functional

`/api/objects/voorzieningen/dienst/export?type=csv` returns 500 Internal Server Error. Both CSV and Excel exports affected.

### 4. HIGH: Mijn Account Personal Data Empty (#266, #352, #353)
**Agents:** Leverancier, Gemeente | **Impact:** Users cannot view/edit personal information

Leverancier sees empty fields ("-") for name/function. Gemeente sees "Geen data gevonden" (generic table instead of personal form). Contact person data not synced to account display.

## Performance Overview

All agents reported acceptable individual API call times. No single API request exceeded the 1000ms PERFORMANCE_FAIL threshold.

### Key Observations

| Observation | Agent | Details |
|-------------|-------|---------|
| ArchiMate view rendering | Arch. Expert | Render <1s for 388 nodes; total page load 9-14s (data prefetching bottleneck) |
| Search page (12,613 results) | Gemeente | Loads quickly, filters responsive |
| Tab switching on detail pages | All | Instantaneous — no visible delay |
| Name resolution delay | Leverancier, Gemeente | 1-2s "Loading..." before names resolve in table columns |
| Backend cache warming | FB | Consistently <1s |
| Single view API call | Arch. Expert | ~530ms (borderline SLOW threshold) |

### Primary Bottleneck
Beheer pages prefetch ALL entity data with `_limit=10000` queries on every load. This accounts for 10+ seconds of total page load time. Individual API calls are fast.

## Environment Limitations

1. **Headless browser** — Export file downloads cannot be verified; export dialogs work but content uninspectable
2. **Single browser engine** — Only Chromium tested; Edge/Firefox differences (#402) unassessable
3. **Local dev environment** — Piwik Pro unconfigured; no email server; production-specific features untestable
4. **Test data gaps** — Some issues require imported data (production migration) not present locally
5. **Viewport sensitivity** — #395 (sidebar) is viewport-dependent: PASS at 1920x1080, FAIL at smaller sizes
6. **Organisation registration gap** — Test Gemeente and Test Samenwerking Nextcloud org IDs don't map to voorzieningen register records, causing persistent 404 errors
